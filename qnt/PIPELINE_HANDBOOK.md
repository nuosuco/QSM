## 盯盘方法论（2026-09-14 中华定稿，基础工作范式，以后严格按此执行）
**盯盘 = 监督程序 + 读市场，是一个持续循环，不是一件事做完了就停：**
```
读三平台市场交易数据(价格/价差/深度/成交量)
  → 边读边分析(哪个币价差在扩大/回归、单边还是震荡、哪个方向在赚钱)
  → 边记录(写 qnt-watch.md / qnt-strategy.md，留证据)
  → 边与三引擎合起来总结规律(回测规律 + 模拟盘规律 + 实盘规律)
  → 边总结规律边升级策略与风控(参数/门槛/仓位/止损/趋势过滤)
  → 边修正升级程序(改代码→重启→验证→继续读下一轮数据)
  → 循环，不停
```
- **程序在读、在分析、在编程迭代中循环，没有"停下来等"这一步**——盯盘本身就是工作流，不是旁观
- 每次醒来：先读盘面(三平台最新数据) → 找当前最严重缺陷(管道/逻辑/风控/数据) → 当场改 → 重启 → 验证 → 再读下一轮 → 继续
- **改完必须验证**（看日志确认新逻辑真跑起来了），没验证 = 未完成，不许宣称做完
- 记录不断：盘面规律、程序缺陷、升级动作，全部落 qnt-watch.md / qnt-strategy.md，下次醒来接着干不重头来
- 风控铁律（2026-09-14 定稿）：20% 仓位管理是风控总纲，适用所有交易/所有资金池，分池 + 双保险，详见第4关

## 核心铁律：利润最大化 + 风险最小化（一切参数决策的评判标准）

### 挂单（开仓）时机——什么时候开单才利润最大、风险最小
1. **价差关卡**：价差 ≥ 0.26%（=0.16%双边成本+0.10%净利门槛），保证开仓即有正期望
2. **趋势关卡**：该币 1h 是震荡（15根5m K线涨跌 <0.15%）且方向不与开仓腿冲突——
   - 开多（赌贴水回归）前 1h 价格跌 >0.15% → 禁止（单边下行中价差不会回归）
   - 开空（赌升水回归）前 1h 价格涨 >0.15% → 禁止（单边上行中价差不会回归）
   - 原理：利润最大化靠"价差回归"，单边市价差只会越拉越大，回归不回来 → 必然止损，开了就是制造风险
3. **冷却关卡**：同交易所同币种 30min 内有亏损平仓 → 禁止再开（防止 ONDO 式连环止损）
4. **仓位关卡（2026-09-14 中华定稿，基础铁律=风控总纲，任何情况不改）**：
   - **20% 仓位管理适用所有交易（永续/其它合约/现货/期货/股票），每个资金池单独算、各留 80% 缓冲**
   - 该平台永续保证金合计 ≤ 该平台永续余额 × 20%（留 80% 在永续里才不爆仓）；现货、其它合约同口径
   - 按【本平台】单独算，不跨平台总算（HTX 池=HTX 的 20%，Gate 池=Gate 的 20%）
   - 已开多少扣多少：本笔 = min(原公式, 该平台永续余额×20% − 该平台已开保证金合计)
   - 双保险：再卡一道该平台总权益 20%（防多路叠加把该平台资金池用穿）
   - 历史爆仓根因：旧代码"每笔都开余额 20%"不扣已开，开 N 笔把该平台永续用了 N×20%（甚至 100%）→ 强平爆亏（HTX 钱亏完、Gate 快亏完）。20% 是【该平台保证金占用总闸】，不是一笔 20% 两笔 40%

5. **杠杆 50x**（Gate 上限 75x，100x 静默失败）：50x 下价差多回归 0.1% = 净利多 0.10%，收益弹性够，爆仓风险可控

### 平仓时机——盈利了怎么平才利润最大化、风险最小化（分档规则，2026-09-13 定稿）
优先级从高到低：
1. **硬止损（风险最小化第一优先）**：标的价格浮亏 ≥ 0.15%（价格口径，不是保证金口径！50x 下标的 0.15%=保证金 7.5%）→ 立即平，砍快
   - 口径说明（2026-09-13 教训）：旧 0.4% 是价格口径却写成"保证金计"，实际价格单边漂移到 3% 才砍，单笔亏 -3.06%。已收紧到 0.15%，与趋势过滤器阈值对齐
2. **止盈（利润最大化核心）**：净利 ≥ 0.10% **且价差在回归（缩小）** → 立即止盈落袋，不贪
3. **让利润跑 ⏳**：净利 ≥ 0.10% **但价差还在扩大** → 不平仓，继续持有（50x 下多回归 0.1% 价差=多 0.10% 净利），直到价差开始回归或到超时线
   - 这是"盈利最大化"和"到点就跑"的本质区别：固定止盈线会砍掉大行情，让利润跑才能吃到 +0.43% 这种超出 0.10% 门槛的机会
4. **价差回归到目标线（SPREAD_CLOSE_THRESHOLD=-0.10%）且净利>0** → 止盈
5. **90分钟超时兜底（防套牢）**：按当前浮盈/浮亏方向无条件切掉——不让单笔单变成长期敞口

### 止损/止盈的盈亏尺度（验证时必须对上的数字）
- 止盈单：净利通常在 +0.10% ~ +0.43%（回放数据），**每笔都要有具体数字**
- 止损单：净利上限 ≈ -(0.15%价格变动 + 0.16%双边成本) ≈ -0.31%，**任何单笔亏损超过 0.31% 都是 bug，先修再验证，不许带病达标**
- 超时单：浮盈或浮亏都可能，记录方向，统计里单独列

## 阶段1：模式二回测，总结规律（每 4h 一次，或发现新单边行情时）
1. 跑：`sqlite3 /root/SOM/data/trading_system/adaptive.db "SELECT exchange, symbol, date(timestamp), COUNT(*), SUM(pnl) FROM engine_trades WHERE mode='live' GROUP BY 1,2,3"`（timestamp 是 unix 秒，北京时间要+8）
2. 结合 DualEngine 模式二日志：`journalctl -u qnt-engines | grep "平台买卖比例"`
3. 回答四个问题写进 `memory/qnt-strategy.md`：
   - 哪些币种净利为正/负？（负→进拉黑名单提案，要中华点头）
   - 哪些时段（UTC）净利最高？（黄金时段 16-23 是否仍成立）
   - 哪些交易所滑点/成本最高？
   - 当前 0.26% 门槛 vs 市场状态（震荡/单边）是否匹配？
4. 产出：一段"规律报告"+ 是否升级程序的决策（升级→进阶段2；不升级→继续观察）
5. **规律总结是静默工作，不需要报中华；但升级决策（改参数/拉黑/调资金）必须中华点头**

## 阶段3：模拟盘验证（铁律：达标前实盘一律"只平不开"，不拿真钱赌逻辑）
### 3.0 前置：数据管道必须是活的（停摆的模拟盘=没验证）
- `sqlite3 /root/SOM/data/trading_system/adaptive.db "SELECT MAX(timestamp) FROM market_data"` 距现在 <10 分钟
- 断更 → 修 `data_collector.py`（查 _collect_loop 线程活着没、connector.connected、fetch 报错），修好后确认 MAX(timestamp) 开始滚动才继续
### 3.1 跑模拟攒数据
- 重启引擎，盯模拟盘日志：`journalctl -u qnt-engines | grep -E "📈 模拟盘|🏁 模拟盘|⏳"`
- 每笔开仓记录：币种/开仓价差/预期净利；每笔平仓记录：触发通道（止盈/止损/超时/让利润跑）/实际净利/持仓时长
### 3.2 达标标准（缺一不可，全部要具体数字，不是"看起来对"）
1. ≥20 笔已平仓交易
2. 每笔止盈净利有具体数字，平均 ≥ 0.10%，且至少观察到 1 次"让利润跑"后止盈净利 > 0.10%（验证分档逻辑真的吃到超额利润）
3. 每笔止损/超时亏损有具体数字，**单笔亏损 ≤ 0.31%**（=0.15%止损线+0.16%成本，超限=bug 回阶段2）
4. 总净利为正，胜率记录在案
5. 明细查询：`sqlite3 adaptive.db "SELECT timestamp, exchange, symbol, pnl, status FROM engine_trades WHERE mode='paper' ORDER BY timestamp DESC LIMIT 30"`
### 3.3 结果处理
- 达标 → 明细表（每笔数字）发给中华确认 → 才进阶段4
- 不达标 → 定位是哪个规则的问题，回阶段2改参数重测，循环，**不带病上线**

## 阶段4：实盘交易（模拟达标 + 中华确认后）
1. 重启引擎，盯日志确认新逻辑标记真实出现（🚫/❄️/🏁/🧹/⏳）
2. 每笔实盘开仓/平仓/止损 → 主动报中华：哪单、哪条规则触发、当前持仓、下一步
3. 实盘数据回流阶段1，4h 规律总结用实盘真实盈亏（不是模拟数）
