```
│     └── 每5分钟对比分析 → 发现盈利规律 → 应用模拟盘          │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 双模式对比原则
1. **一致性才信任**：只有两种模式结果一致，才确认策略有效
2. **历史优先**：结果不一致时，优先相信我们的真实成交数据
3. **快速应用**：盈利规律立即应用到模拟盘，亏损规律立即止损

### 1.3 完整流程
```
双模式回测（模式一+模式二）
    → 对比验证（一致性检查）
    → 发现规律（盈利币种/平台）
    → 应用模拟盘（per-platform独立测试）
    → 模拟验证（≥24h盈利达标）
    → 用户确认
    → 实盘交易（铁律防护）
```

## 三、风控铁律（三平台统一）

### 3.1 核心参数（定死不变）
- **成本线**：0.16%（BI_SIDE_COST）
- **最小净利**：0.01%（MIN_NET_PROFIT_PCT）
- **价差门槛**：>0.17%（实际要求）

### 3.2 风控阈值（不可改）
- 单笔仓位：≤总资金20%
- 连续亏损：3次暂停
- 最大回撤：30%停止
- 实盘开关：config.live.enabled=False（默认关闭）
- 盈利提取：50%永不回流

### 3.3 可调参数（只影响灵敏度）
- spread_pct：价差阈值（可调整）
- net_profit_pct：净利阈值（可调整）

## 五、双模式进化机制

### 5.1 进化流程
```
每5分钟：
  1. 对比双模式数据
  2. 统计各币种盈利/亏损
  3. 发现共同盈利规律
  4. 应用到模拟盘测试
  5. 记录进化历史

每日：
  1. 分析24h进化报告
  2. 更新策略优先级
  3. 调整参数（如需要）
  4. 保存进化报告
```

### 5.2 进化动作类型
- **confidence_boost**：双模式均盈利 → 提升信心，可适当放宽门槛
- **risk_reduction**：双模式均亏损 → 收紧风控，提高门槛
- **priority_adjust**：共同盈利币种 → 提升优先级
- **investigate**：双模式分歧 → 深入分析差异原因

## 六、数据库表结构

### 6.1 模式一数据
- `historical_trades`：我们的真实成交（含exchange字段）
  - 字段：timestamp, exchange, symbol, side, price, amount, cost, fee, order_id

### 6.2 模式二数据
- `market_trades`：平台公开市场成交（含exchange字段）
  - 字段：timestamp, symbol, exchange, spread_pct, side, perp_price, spot_price, amount, cost, fee, pnl, pnl_pct, status, order_id

- `market_data`：价差数据（含exchange字段）
- `engine_trades`：引擎交易记录（含exchange、mode字段）
- `simulated_platform_balance`：模拟余额（per-platform）
- `evolution_history`：进化历史
