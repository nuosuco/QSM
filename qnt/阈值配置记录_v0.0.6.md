## 🔢 核心公式（记住！）

```
实际交易门槛 = BI_SIDE_COST(0.12%) + MIN_NET_PROFIT_PCT(0.1%) = >0.22%
      ↑                ↑
   交易所成本        风控最低要求
```

- ✅ 改 `spread_pct` / `net_profit_pct` → 只改变灵敏度，**不影响实际门槛**
- ⚠️ 改 `MIN_NET_PROFIT_PCT` → 实际门槛跟着变（比如改0.05% → 门槛变0.17%）
- ❌ 改 `BI_SIDE_COST` → 不要改！这是交易所真实费率

---

```
BI_SIDE_COST = 0.12% = 双边成本（手续费+滑点）

计算逻辑：
  净利 = 价差 - 0.12%
  
  价差 = 0.12% → 净利 = 0% → 不赚不亏（保本）
  价差 > 0.12% → 净利 > 0 → 开始盈利
  价差 < 0.12% → 净利 < 0 → 一定亏钱
```

## 四、执行引擎阈值（可调整）

### 1️⃣ 价差阈值 `spread_pct`
- **当前值**：0.05%
- **作用**：价差大于这个数才看
- **风控底线**：必须 < 0.12%（成本线），否则永远看不到机会
- **可改吗**：✅ 可以改
- **改了会怎样**：
  - 改成0.03% → 更敏感，更多机会（但可能亏钱）
  - 改成0.10% → 更保守，更少机会（但更稳）

**联动关系**：
```
spread_pct 改小（如0.03%）：
  → 执行引擎更早看到机会
  → 但风控层仍然要求净利>0.1%
  → 实际要求价差仍然是 >0.22%
  → 结论：改spread_pct只影响"看"的灵敏度，不影响"做"的底线

spread_pct 改大（如0.10%）：
  → 执行引擎更晚看到机会
  → 但风控层仍然要求净利>0.1%
  → 实际要求价差仍然是 >0.22%
  → 结论：改spread_pct不影响最终交易条件
```

**大白话**：这就像你买东西，价差太小你不感兴趣，价差大你才考虑。改成0.03%就是"稍微有点利差就看一眼"，改成0.10%就是"利差必须够大我才动"。但不管你看没看，最后都要风控层点头才行。

---

### 2️⃣ 净利阈值 `net_profit_pct`
- **当前值**：0.01%
- **作用**：净利大于这个数才交易
- **风控底线**：必须 < 0.1%（风控层MIN_NET_PROFIT_PCT），否则永远无法通过风控
- **可改吗**：✅ 可以改
- **改了会怎样**：
  - 改成0 → 不亏钱就交易（但风控层仍然要求>0.1%）
  - 改成0.05% → 必须有利润才交易（但风控层仍然要求>0.1%）

**联动关系**：
```
net_profit_pct 改小（如0.005%）：
  → 执行引擎更容易触发
  → 但风控层仍然要求净利>0.1%
  → 实际要求价差仍然是 >0.22%
  → 结论：改net_profit_pct只影响"触发"灵敏度，不影响"成交"底线

net_profit_pct 改大（如0.05%）：
  → 执行引擎更难触发
  → 但风控层仍然要求净利>0.1%
  → 实际要求价差仍然是 >0.22%
  → 结论：改net_profit_pct不影响最终交易条件
```

**大白话**：这就像你做生意，0.01%就是"不亏就行"，0.05%就是"至少赚点才行"。但不管你怎么说，老板（风控层）说至少赚0.1%才行。所以你改什么，老板说了算。

---

### 3️⃣ 双边成本 `BI_SIDE_COST`
- **当前值**：0.12%
- **作用**：交易成本（手续费+滑点）
- **可改吗**：⚠️ 不建议改（这是交易所实际费率，改了会导致计算错误）

**大白话**：这是交易所收你的钱，你改不了。永续合约收0.04%，现货收0.02%，滑点再算0.02%，加起来单边0.06%，双边就是0.12%。这个是固定的，别改。

**成本线概念**：
```
价差 = 0.12% → 不赚不亏（保本）
价差 > 0.12% → 开始盈利
价差 < 0.12% → 一定亏钱
```

## 五、风控层阈值（定死不变）

### `MIN_NET_PROFIT_PCT`
- **当前值**：0.1%（**定死**）
- **作用**：风控级别的最小净利要求
- **可改吗**：❌ **定死不变**
- **改了会怎样**：
  - 改成0.05% → 更宽松（实际要求价差>0.17%）
  - 改成0.2% → 更严格（实际要求价差>0.32%）

**联动关系**：
```
MIN_NET_PROFIT_PCT 改小（如0.05%）：
  → 实际要求价差 = 0.12% + 0.05% = 0.17%
  → 所有其他阈值不需要变
  → 但整个系统风险变大

MIN_NET_PROFIT_PCT 改大（如0.2%）：
  → 实际要求价差 = 0.12% + 0.2% = 0.32%
  → 所有其他阈值不需要变
  → 但整个系统更保守
```

**大白话**：这是风控层面的要求，比执行引擎的阈值更高。执行引擎说"0.01%就交易"，风控说"不行，至少0.1%才允许"。

⚠️ **注意**：这是风控铁律，不应随意修改！

**实际要求**：
```
净利 > 0.1% → 价差必须 > 0.12% + 0.1% = 0.22%
```

## 六、模式发现阈值（不影响实盘交易）

### `spread_threshold` / `profitable_spread`
- **当前值**：0.08% / 0.10%
- **作用**：用于策略分析，不是直接控制交易
- **可改吗**：✅ 可以改，但不影响实盘交易
- **风控底线**：`spread_threshold` ≤ 0.12%（成本线），`profitable_spread` > `spread_threshold`

**联动关系**：
```
spread_threshold 改小（如0.05%）：
  → 模式发现更容易识别"价差异常"
  → 但不影响实盘交易条件

spread_threshold 改大（如0.10%）：
  → 模式发现更难识别"价差异常"
  → 但不影响实盘交易条件

profitable_spread 必须 > spread_threshold
  → 如果spread_threshold=0.08%，profitable_spread应该=0.10%
  → 两者差值=0.02%（安全边际）
```

**大白话**：这两个参数是给"模式发现引擎"用的，用来分析历史数据找规律。不改它们，实盘交易照样跑。改了只是影响分析报告，不影响实际挂单。
