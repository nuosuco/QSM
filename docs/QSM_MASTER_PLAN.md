## 二、真实现状（诚实评估）

### 2.1 有效资产

| 文件 | 行数 | 说明 |
|------|------|------|
| qcl.qentl | 1383 | 唯一真正的QEntL编译器，能编译fib等简单程序 |
| lib/math.qentl | ~50 | 数学库 |
| src/qcl_bootstrap.c | ~247 | C启动器，只认量子指令(init/H/CNOT/MEASURE等) |
| data/*.jsonl | 390M | 彝文训练数据，4120字三语对照 |
| docs/ | 4个文件 | 核心文档 |

### 2.2 qcl.qentl能力评估

**能做的**：
- 词法分析（tokenize）
- 函数定义（def）和调用
- var/const声明
- if/else、while循环
- 算术运算、比较运算
- printf输出（单参数%d）
- 递归（CallFrame变量快照）
- import（已修复buffer生命周期）

**不能做的（自举瓶颈）**：
- str_*内置函数（79处调用）
- 数组索引表达式（416处）
- 多参数printf
- 字符串字面量作为函数参数传递
- 复杂表达式嵌套

## 三、构建路径（八阶段自举链）

### 总览

```
阶段1: C启动器编译量子指令子集 ← 已有，不动
    ↓
阶段2: 给qcl.qentl补str_*和数组索引 ← 当前瓶颈
    ↓
阶段3: qcl.qentl编译自己（自举）
    ↓
阶段4: 自举后的QCL编译QVM源码 → QVM.qbc
    ↓
阶段5: C启动器加载QVM.qbc → QEntL运行环境形成
    ↓
阶段6: QCL在QVM中编译QDFS/QNS/四大模型
    ↓
阶段7: QNS训练彝文，四大模型运行，更新Web API
    ↓
阶段8: 三种部署（虚拟机/Web QOS/终端QOS远期）
```

### 阶段1: C启动器（已完成，不动）

- `src/qcl_bootstrap.c` 编译为 `bin/qcl_bootstrap`
- 只认量子指令：init/H/X/Y/Z/T/S/CNOT/MEASURE/PRINT/STOP
- 输出raw opcodes，QVM从位置0读取
- **红线：不在这个文件里加任何新功能**

### 阶段2: 补全qcl.qentl（当前工作）

**2a. 添加str_*内置函数**（79处调用）
```
str_len(s) → 返回字符串长度
str_char_at(s, i) → 返回第i个字符的ASCII码
str_substring(s, start, len) → 返回子串
str_concat(a, b) → 拼接两个字符串
str_eq(a, b) → 字符串相等比较
str_index_of(s, sub) → 查找子串位置
str_from_char(c) → ASCII码转字符
str_to_int(s) → 字符串转整数
int_to_str(n) → 整数转字符串
```

**2b. 添加数组索引表达式**（416处）

当前：`arr[i] = val` 能编译（赋值目标）
缺失：`var x = arr[i]` 不能编译（表达式中的索引）

需要：在表达式解析器中识别 `IDENT [ expr ]` 模式

**2c. 多参数printf**

当前只支持 `printf("%d", x)` 单参数。
需要支持 `printf("%d + %d = %d", a, b, c)` 多参数。
