## 二、当前推理流程 (handler_v14)

```
请求 GET /api/yi?d=xxx
  │
  ├→ batch = d / 515  (路由到对应批)
  ├→ row = d % 515    (批内行号)
  │
  ├→ 加载 yi_flat_b{batch}.bin (64像素数据)
  │
  ├→ 串行4态:
  │   load qscl_b{batch}_s0.w → 点积argmax → v0
  │   load qscl_b{batch}_s1.w → 点积argmax → v1
  │   load qscl_b{batch}_s2.w → 点积argmax → v2
  │   load qscl_b{batch}_s3.w → 点积argmax → v3
  │
  └→ 投票: votes>=2 → OK (多数同意)
```

### 点积公式
```
对每个类c(0..514):
  dot[c] = Σ(W[c*64+j] * data[row*64+j])  j=0..63
预测 = argmax(dot)
```

## 三、叠加态并行的本质

### 是什么
- 4个模型从**不同随机起点**独立训练
- 对同一输入各自算出预测
- **投票**(多数同意)决定最终结果
- 效果: 比单模型更准(99.83% vs 单态~99%)

### 不是什么
- **不是量子纠缠**: 底层是经典整数运算,没有量子比特
- **不是自动选择知识**: 是全部4态都算一遍,投票决定
- **不是真并行(当前)**: 4态串行加载计算,有I/O延迟

### 中华确认
"出来32份才是正确的叠加态并行"
- 32份各自独立 = 真不同起点 = 真叠加态
- 合成1个 = 单模型 = 放弃叠加态优势
- 命名"叠加态并行"合理: 不同态看同一问题不同角度,合议更准

## 四、当前局限 vs 未来目标

| 维度 | 当前 | 未来目标 |
|---|---|---|
| 4态执行 | 串行(一个接一个) | 并行(同时算4态)→快4倍 |
| 权重加载 | 每次磁盘读文件(~100KB) | 内存常驻/共享内存 |
| 覆盖范围 | 只认字(正向QSCL) | +输出(反向QSCL)+语言(LM) |
| 调用粒度 | 单字d→batch路由 | 全图/全句/全视频 |
| 输出能力 | 无 | 文字/图片/音频/视频统一并行输出 |

## 五、统一输出架构(三算子)

```
算子1 QSCL识别器(看): 像素→标签     ✅已实现(32份权重)
算子2 反向QSCL(画/写): 标签→像素     ⬜待建(权重=正向转置初始化)
算子3 QSCL-LM(想/生成): 标签序列→下一标签 ⬜待建(81维→515×81→argmax)

文字生成 = 算子3循环 + 算子2收尾(标签→字形像素)
图片生成 = 算子3画布局 + 算子2画部件(标签→视觉像素)
视频生成 = 帧序列 + 时序(算子1认每帧 + 算子3预测下帧)
音频生成 = 声波像素(频谱→像素→标签→反向QSCL→波形)
```

## 六、★ 算子1↔2 对称本质(2026-08-23 中华洞察)

识别与生成共用**同一份 W、同一套 4 态、同一套 4 进程真并行**——不分类、不重训、不新起炉灶。

**识别(算子1, 已 99.44%)**: `data(64像素) · W[c*64..] → dot[c] → argmax → 类序号 k`
**生成(算子2, 待建)**: `类序号 k → 取 W[k*64..(k+1)*64] → 4态并行取行 → 4张像素投票坍缩 → 阈值化 → 8×8二值图 → 光栅化彝文`

核心洞见: Hebbian 训练让 W[k] 收敛到"第 k 类的原型像素向量",所以 **W[k] 本身就是那个字的原型图像**。生成不需要新模型、不需要反向传播(QVM 无浮点本就不支持),只需把 W[k] 当图像倒过来渲染。

**4 态并行坍缩(铁律兑现)**: 态0/1/2/3 各自加载 `qscl_b{batch}_s{0..3}.w` 取第 k 行像素, 4 张图逐元素多数投票 → 1 张稳定像素 → 光栅化输出。全程仍是 4 个 QVM 进程真并行,与识别完全对称。

**为什么"非常简单"**:
1. 输入输出都是**像素**——识别=像素→序号,生成=序号→像素,数学上互为逆运算
2. 看/想/写**共用同一个 W**,不分类不重建
3. 4 态真并行已跑通(0.2s/查询),生成直接复用同一套并行骨架
4. 无需新训练——W[k] 是现成原型,取行+阈值+投票即可

**后续所有模态同此理**: 文字=算子3循环(序号流)+算子2收尾(序号→字形像素); 图片=算子3画布局+算子2画部件; 音频/视频=频谱/帧转像素后复用同一算子1↔2对称核。

## 七、并行总纲(铁律, 2026-08-22 中华定)

> ★ 中华原话: "哪里都应该是并行, 只是我们现在是4态, 所以哪里都应该是
> 4态不同起点叠加态并行, 不能是串行, 搞假的叠加态哈。"
> 串行 = 假的叠加态 = 错。

**"叠加态并行"不是识别器的专属特性, 而是贯穿整个生态(看/读/文字/图片/音频/视频)的架构铁律。**

- 旧: handler_v14 / yi_infer.sh 旧版, `for s in 0 1 2 3` 串行, ~5.2s/查询(**已退场回收**)
- 升级: 4个QVM进程真并行, ~0.2s/查询, **提速约25倍**
- 7/7 批实测4态并行全部投票正确

### 判定(三问, 任一不满足=假并行=禁止)
1. 4态是否同时运行? 2. 不同随机起点? 3. 最后才汇聚投票?
