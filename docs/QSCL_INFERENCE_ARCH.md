## 一、32份权重文件结构

```
qdfs/ns/models/
├── qscl_b0_s0.w  ─┐
├── qscl_b0_s1.w  │ 批0, 4态(seed 1/101/202/303)
├── qscl_b0_s2.w  │ 每份515×64=32960整数
├── qscl_b0_s3.w  ─┘
├── qscl_b1_s0.w  ─┐ 批1, 4态
...                 │
└── qscl_b7_s3.w    ─ 批7, 4态
```

- 8批 × 4态 = 32份
- 每份覆盖515个字, 8批覆盖4120字
- 4态不同随机起点(seed 1/101/202/303)→学到不同知识→投票
- 文件大小各不相同(114KB~134KB)证明权重值确实不同=真叠加态

## 二、当前推理流程 (handler_v14)

```
请求 GET /api/yi?d=xxx
  │
  ├→ batch = d / 515  (路由到对应批)
  ├→ row = d % 515    (批内行号)
  │
  ├→ 加载 yi_flat_b{batch}.bin (64像素数据)
  │
  ├→ 串行4态:
  │   load qscl_b{batch}_s0.w → 点积argmax → v0
  │   load qscl_b{batch}_s1.w → 点积argmax → v1
  │   load qscl_b{batch}_s2.w → 点积argmax → v2
  │   load qscl_b{batch}_s3.w → 点积argmax → v3
  │
  └→ 投票: votes>=2 → OK (多数同意)
```

### 点积公式
```
对每个类c(0..514):
  dot[c] = Σ(W[c*64+j] * data[row*64+j])  j=0..63
预测 = argmax(dot)
```

## 三、叠加态并行的本质

### 是什么
- 4个模型从**不同随机起点**独立训练
- 对同一输入各自算出预测
- **投票**(多数同意)决定最终结果
- 效果: 比单模型更准(99.83% vs 单态~99%)

### 不是什么
- **不是量子纠缠**: 底层是经典整数运算,没有量子比特
- **不是自动选择知识**: 是全部4态都算一遍,投票决定
- **不是真并行(当前)**: 4态串行加载计算,有I/O延迟

### 中华确认
"出来32份才是正确的叠加态并行"
- 32份各自独立 = 真不同起点 = 真叠加态
- 合成1个 = 单模型 = 放弃叠加态优势
- 命名"叠加态并行"合理: 不同态看同一问题不同角度,合议更准

## 四、当前局限 vs 未来目标

| 维度 | 当前 | 未来目标 |
|---|---|---|
| 4态执行 | 串行(一个接一个) | 并行(同时算4态)→快4倍 |
| 权重加载 | 每次磁盘读文件(~100KB) | 内存常驻/共享内存 |
| 覆盖范围 | 只认字(正向QSCL) | +输出(反向QSCL)+语言(LM) |
| 调用粒度 | 单字d→batch路由 | 全图/全句/全视频 |
| 输出能力 | 无 | 文字/图片/音频/视频统一并行输出 |

## 五、统一输出架构(三算子)

```
算子1 QSCL识别器(看): 像素→标签     ✅已实现(32份权重)
算子2 反向QSCL(画/写): 标签→像素     ⬜待建(权重=正向转置初始化)
算子3 QSCL-LM(想/生成): 标签序列→下一标签 ⬜待建(81维→515×81→argmax)

文字生成 = 算子3循环 + 算子2收尾(标签→字形像素)
图片生成 = 算子3画布局 + 算子2画部件(标签→视觉像素)
视频生成 = 帧序列 + 时序(算子1认每帧 + 算子3预测下帧)
音频生成 = 声波像素(频谱→像素→标签→反向QSCL→波形)
```
