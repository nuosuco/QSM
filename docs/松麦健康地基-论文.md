## 摘要

健康管理行业长期存在一个被忽视的根本问题：数据没有地基。用户每天产生大量健康相关行为（问诊、饮食、睡眠、运动、体质测评），但这些数据散落在聊天记录、纸质本子、各机构系统里，彼此割裂、无法积累、无法追踪，更无法"越用越懂你"。本文提出并论证：**健康数据要成为真正的"健康大数据"，必须建立在"一人一户、身份唯一、时间连续"的地基之上**。

松麦（SOM）是这个理论的系统实现。它是一个"中医辨证 + 药食同源 + 游戏化养生"的智能平台，核心能力是让 AI 助手"小麦SOM"记住每一个用户——不管用户来多少次、换多少次会话、甚至照片里的人老了换了角度，系统都认得他、记得他、并且随时间积累他的健康时间线。本文从理论基础（一人一户、身份识别、辨证引擎、数据壁垒）到工程实现（ArcFace 本地人脸向量、双通道体质提取、会话持久化、健康画像时间线、四账户统一认证、有机商品链路），完整给出松麦"健康地基"是怎么一层层垒起来的，以及未来"训练全世界第一健康大模型"的演进路径。

关键词：健康大数据；中医辨证；一人一户；身份一致性；健康档案；食疗方案；AI 助手；数据壁垒

## 1. 问题与理论：为什么健康数据需要"地基"

### 1.1 行业现状：数据很多，地基没有

健康管理行业不缺数据——App、体检报告、智能手环、问诊记录每天都在产生。但这些数据普遍存在三个致命缺陷：

- **身份割裂**：同一个人在不同会话、不同设备、不同登录方式（匿名/账密/邮箱/微信）下，系统看到的是"不同的人"，数据无法归并。
- **时间断裂**：数据是快照式的，一次问答一条记录，缺乏"这个人随着时间身体在怎么变化"的连续时间线。
- **没有沉淀**：数据用完即弃，不积累、不学习，越用不越准，用户感知不到"被记住"。

结果：大多数健康产品做五年和做一年没有本质区别，因为没有数据复利。

### 1.2 我们的命题：健康大数据必须"一人一户"

松麦的核心命题是：**一个自然的人 = 一个唯一账户 = 一条连续的健康时间线**。

只有当"身份"被牢牢锚定（不重复、不混淆、不误认），后续的"体质记录随时间积累""照片特征随年龄演化""辨证结论随生活变化"才成立。这就是"地基"的含义——地基不牢，上面的楼（健康大模型、个性化推荐、主动关怀）全部塌。

由此引出四层结构（详见第 2 节）：身份层 → 辨证层 → 档案层 → 应用层。

## 2. 松麦理论体系：健康地基的四层结构

```
┌─────────────────────────────────────────────┐
│ 应用层：AI 主动关怀 / 食疗方案 / 有机商品推荐     │
├─────────────────────────────────────────────┤
│ 档案层：tizhi_records + 健康画像时间线          │
│        （每次辨证 1 条，随时间积累）             │
├─────────────────────────────────────────────┤
│ 辨证层：LLM 视觉辨证 + 规则引擎 BianzhengEngine  │
│        + RAG 知识库（药食同源/九种体质/食疗）     │
├─────────────────────────────────────────────┤
│ 身份层：ArcFace 本地人脸向量 + 一人一户 + 拒档    │
│        （谁在拍照？是不是本人？认错就拒档）        │
└─────────────────────────────────────────────┘
```

- **身份层**：用本地人脸识别把"照片里的人"锚定到"数据库里的 user_id"，且只有本人的照片才允许进入健康档案，别人的照片拒档，从源头堵住数据污染。
- **辨证层**：图片辨证走 LLM 视觉（拍舌苔/面色/患处），文字辨证走规则引擎兜底，两者输出统一的"体质 + 证型 + 建议"结构。
- **档案层**：每次辨证产生一条 `tizhi_records` 记录（一辨证=一记录，绝不按会话去重覆盖），档案随使用次数自然增厚。
- **应用层**：基于档案给出个性化食疗、节气主动关怀、有机商品推荐（淘宝联盟佣金闭环）。

四层从下往上层层依赖：身份错 → 档案污染 → 辨证失真 → 应用失效。地基（身份层）是全部能力的根。

## 3. 关键机制之一：身份识别（一人一户）

### 3.1 谁认脸：本地 ArcFace，不靠 LLM

认脸**不是小麦（LLM）做的**，而是服务端本地跑的 insightface `buffalo_l`（ArcFace 识别 + det_10g 检测，onnxruntime CPU，懒加载）。LLM 只负责"看舌苔/面色/患处做辨证"，不认人。这样既避免把人脸发给云端（隐私），也保证身份判断可控、可审计。

**隐私合规：只存 512 维特征向量（base64 约 2KB），不存原图**；用户删账号时向量一并清除。

### 3.2 向量组学习：人会变老，系统要认得

`face_vectors` 表按 `(user_id, model_version)` 命名空间，一个用户可存多条历史向量：

- 累加不覆盖；与组内余弦 > 0.98 视为同脸，只刷新最近一条；上限 24 条，超出丢最老。
- 比对时对该用户**全部历史向量取均值**再算余弦 → 用户变老/换角度/换光线仍能认出。
- 换模型版本 = 新命名空间，旧向量自动作废。

这是"健康地基"能"陪用户一辈子"的技术保证——地基随用户年龄一起"生长"。

### 3.3 非本人照片拒档：一人一户的最后一道闸

入库前置校验（先判后存）：

- 该用户已有向量组时，新脸向量必须同时满足：① ArcFace 检到真脸；② 与组均值余弦 ≥ 阈值（实测 0.42）。全过才入库，否则拒存。
- 拒档行为：不写 `tizhi_records`（不污染健康档案）、不把别人的脸向量塞进向量组（不污染识别）、小麦大白话提示"这不是你本人的照片，请用本人真实照片重新拍"。
- 放行不误伤：首次建档（组空）放行；检不到脸（纯舌苔照）写真档案放行但向量拒存；本人照片（余弦≥阈值）放行存档。

> 历史教训：拒档曾反复失效，根因不是阈值，是"别人的脸向量被先存进组"（旧代码先存后判），组被污染后余弦被拉高，拒档永远显示"本人"。修法是改"先判后存"。这条经验直接印证了地基理论：**身份层的污染是不可逆的，必须从源头拦住**。

## 4. 关键机制之二：辨证引擎与体质提取（双通道）

### 4.1 双通道体质提取

体质数据**不靠前端 JS 从 LLM 回复里正则抓**（浏览器缓存旧版 JS 就丢数据）。图片辨证和文字辨证都走**服务端自动存档**：

- **通道 1**：解析 LLM 末尾固定 JSON 块 `tizhi_data: {"tizhi":"...","zhengxing":"..."}`（提示词要求 LLM 输出，优先用）。
- **通道 2**：兜底 = 9 型体质词表 + 兼有/证型正则，通道 1 没抓到才跑。

两种回复格式都能落库，双保险。

### 4.2 规则引擎兜底（LLM 挂了也不瞎）

`BianzhengEngine` 是可控、可审计的规则辨证引擎：症状 → 证型 → 体质判定，不依赖 LLM。云端 LLM（SenseNova/Agnes/GLM 三级自动降级）挂了，规则引擎顶上，保证辨证服务永远在线。

### 4.3 RAG 知识库

四个 JSON 知识库：

- `bianzheng.json`（30 类症状→证型）
- `tizhi.json`（9 种体质）
- `yaoshi_tongyuan.json`（60 味药食同源食材）
- `shiliao.json`（82 个食疗方案）

辨证结果 + 知识库 = 个性化食疗方案，方案里每种食材带 2 款有机认证商品（淘宝联盟佣金链接）。

## 5. 关键机制之三：会话持久化与终身用户档案

松麦最大的特色优势（中华原话）：**不管小麦经历多少次新会话，它都认识这个用户，好像相识几年了一样。**

工程实现：

- **会话持久化**：前端从 `sessionStorage` 改为 `localStorage`，关闭浏览器再打开，session_id 不变，小麦记得之前对话。
- **终身用户档案**：每次对话加载该用户全部历史对话（最近 30 条）+ 体质记录（最近 5 条）。老用户回来，小麦主动打招呼："上次你说 XX，最近好点了吗？"
- **节气主动关怀**：对话开始时注入当前节气信息，小麦结合用户体质给出当日建议："今天大暑，你之前说容易疲倦，建议……"

这就是"越用越懂你"——不是功能，是数据复利。

## 6. 关键机制之四：健康画像——多维时间线

用户随时间变老，照片向量也在变。松麦在个人中心出"健康画像"，是多维时间线而非单点快照：

- **数据列**：`tizhi_records.photo_features`（该次拍照第一张图的 512 维视觉特征）+ `photo_hash`（短指纹，趋势去重展示）。仅拍照辨证填，文字辨证为 NULL。
- **接口** `GET /api/health/portrait?user_id=&days=0&offset=0`：
  1. 辨证时间线（相邻两次有照片行算 `visual_delta` = 1-余弦，0≈几乎一样、越大越不同）
  2. 人脸向量组规模/首末时间
  3. 体质分布
  4. 首末体质趋势（changed）
  5. 注册天数
- **口径**：`days=0` = 全量，与体质记录卡片条数统一。
- **分页**：真翻页，每页 10 条，累积式 append。
- **时区**：库内时间统一北京时间（UTC+8），前端直接用，不双重换算。

健康画像就是用户"自己看得见的健康地基"——他能看到自己的体质在怎么变、照片特征在怎么漂移、连续多少天记录。这是把"地基"变成用户可感知产品的关键一步。

## 7. 关键机制之五：有机商品链路（食疗方案 → 可购买商品）

松麦的变现逻辑：**不卖货，卖"对症的养生方案"。货只是方案的载体。**

- 辨证出食疗方案（含食材 + 用量）→ 每种食材推荐 2 款**有机认证**商品（淘宝联盟 `click_url` 佣金链接）。
- 商品推荐铁律：必须含"有机"二字；必须是食材（排除原浆/口服液/胶囊等加工品）；食材必须是商品主体；每食材 2 款不同品牌；宁缺毋滥。
- 痛点人群（三高/痛风/风湿/糖尿病）是最强付费动力：他们每天都在找"吃什么能降尿酸/降血糖"，转化动力远超养生爱好者。

这条链路把"健康地基"上的数据，接上了"有机食品"这条可变现、可持续的腿——数据越准 → 方案越对症 → 用户越信 → 买得越多 → 数据越多。

## 8. 统一认证：四种登录方式归一到同一 user_id

一人一户的前提，是"微信/账密/邮箱/匿名"四种登录方式最终必须归到**同一个 user_id**。

- 微信服务号 OAuth2.0 网页登录（域名已备案审核通过），回调必须把匿名 user_id 传进 `wechat_web_login`，触发后端数据合并。
- 匿名数据合并走 `user_system._merge_anonymous`，迁移 4 张表（tizhi_records / chat_history / search_history / checkin_records）+ product_favorites 逐行去重。**新增任何按 user_id 存的用户数据表，必须把表名加进合并列表**，否则登录即数据断档。
- 密码/邮箱/注册入口都带 `anonymous_user_id` 参数，登录成功/失败都跳个人中心。

这是地基的"门"——四种登录方式，进的是同一个家。

## 9. 系统架构与实现总览

```
SOM（松麦）
├── 小麦SOM（核心助手）
│   ├── 对话式中医辨证 → 个性化养生方案 → 有机食材推荐
│   ├── 图片辨证（拍舌苔/面色/患处，LLM 视觉）
│   └── 食谱商品推荐（每食材 2 款有机认证商品，淘宝联盟）
├── 有机好物（商城）：21 分类，淘宝联盟实时搜索
├── 养生谷：九种体质 + 药食同源百科 + 节气养生 + 健康测评入口
├── 健康测评页：AI 拍照扫描（最强裂变钩子）+ 体质测评 + 症状自评
├── 个人中心：体质档案 + 签到积分 + 健康画像时间线 + 统一认证
└── 未来：护眼训练 / 节气游戏 / 积分商城 / som.skill 开放 API

技术栈：
- 前端：原生 HTML/CSS/JS（som.top）+ 微信小程序
- 后端：Python FastAPI + Uvicorn（systemd som-api，端口 8000）
- 模型：云端 LLM（SenseNova 主力 / Agnes 备用 / GLM 兜底）+ 本地 ArcFace
- 知识库：RAG（关键词检索 + 4 个 JSON 库）
- 数据库：SQLite（用户/对话/体质记录/人脸向量/签到）
- 商品：淘宝联盟 API（click_url 佣金）
- 服务器：2 核 8G 无 GPU（前期够用，后期按需租 GPU）
```

关键工程数字（截至 2026-10）：后端约 1.1 万行 Python + 前端 3300 行 JS；89 个 HTTP API；4 个 RAG 知识库共 181 条核心知识；`tizhi_records` 已有 36 条记录、12 个用户；`face_vectors` 按一人一组管理。

## 10. 未来演进：训练"松麦健康大模型"

理论上的终极一步：**用平台积累的用户辨证数据，训练一个"全世界第一健康大模型"。**

- 数据资产：每一个用户、每一次辨证、每一条体质时间线、每一组人脸向量、每一条食疗反馈，都是训练语料。
- 冷启动：先用云端 LLM + RAG + 规则引擎（现状，零成本）；
- 数据积累期：辨证数据量级上来后（目标数亿用户级），用自有数据微调"中医养生专用"大模型；
- 终极形态：松麦不再是一个 App，而是一套"养生能力 API"（som.skill），供网页/小程序/购物助手/第三方接入。

从"地基"到"大模型"的路径是清晰的：地基（一人一户 + 身份 + 档案）→ 复利（越用越准）→ 数据壁垒（抄不走）→ 自有大模型（全世界第一健康大模型）。

## 11. 结论

健康大数据的瓶颈从来不是"数据够不够多"，而是"数据有没有地基"。松麦用四层结构（身份层-辨证层-档案层-应用层）把"一人一户"垒成坚实地基：本地 ArcFace 锚定身份、双通道辨证沉淀体质、会话持久化实现终身档案、健康画像让时间线可见、有机商品链路让数据可变现、四种登录归一让地基的门只开一次。

这套地基的价值是复利式的——用户用一天，多一层；用一年，厚一年。它不是功能，是资产。而在这套资产之上，"松麦健康大模型"是理所当然的下一步。

> 松麦，为每一个人、每一个家庭的健康服务。健康地基，才立得牢楼。
