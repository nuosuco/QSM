# SOM 松麦 - 项目总方案

> 有机认证 · 药食同源 · 健康环保 · 中医养生

## 项目概述

**项目名称：** SOM（松麦）  
**域名：** som.top  
**助手名称：** 小麦SOM  
**定位：** 中医辨证 + 有机认证药食同源 + 游戏化养生的健康生活平台

**核心理念：**
- 不卖货，卖"对症的养生方案"
- 不教课，让用户在玩中学会养生
- 不强调技术，用户感受到的是一个懂你的养生伙伴

**产品标准：**
- 只做有机认证的有机食品
- 只做药食同源食材（有正规资质）
- 只做健康环保认证的健康产品
- 不做无资质证明的"原生态"产品

## 技术架构

### 核心引擎

```
小麦SOM = 云端LLM（SenseNova/Agnes/GLM）+ RAG知识库 + 规则辨证引擎
```

- **云端LLM**：
  - SenseNova 6.7 Flash-Lite（主力 priority=1，支持文字+图片识别）
  - Agnes 2.5 Flash（备用 priority=2，支持文字+图片识别+图片生成+视频生成）
  - GLM 5.2（备用 priority=3，仅文字）
  - 自动降级：LLM 挂了 → 规则辨证引擎（BianzhengEngine）
- **内容生产模型**：
  - Agnes 2.5 图片模型 → 种草配图、视频画面
  - Agnes 2.5 视频模型 → 短视频片段（5-10秒/段）
  - ffmpeg → 视频合成（拼接+配音+字幕+背景音乐）
- **RAG知识库**：中医辨证逻辑 + 药食同源食材库 + 体质辨识体系 + 食疗方案
- **规则辨证引擎**：症状→证型→体质判定，可控可审计，不依赖LLM
- 所有功能模块共享同一引擎和知识库

### 技术栈（实际）

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 前端-微信小程序 | 原生小程序框架 | 微信生态，v1.0.7 已上传审核 |
| 前端-网页版 | 原生 HTML/CSS/JS（SPA） | som.top，nginx 托管 |
| 后端服务 | Python FastAPI + Uvicorn | systemd 服务 `som-api.service`，端口 8000 |
| 模型推理 | 云端API（SenseNova/Agnes/GLM） | 免费额度，多模型自动降级 |
| 知识库 | RAG（关键词检索 + JSON知识库） | 中医辨证 + 药食同源 |
| 数据库 | SQLite | 用户数据、对话记录、积分系统 |
| 商品对接 | 淘宝联盟API | 佣金模式，click_url 跳转 |
| 服务器 | 2核8G 无GPU，国内 | 腾讯云 |

### 部署方案

**当前（第一阶段）：**
- 服务器：2核CPU / 8GB内存 / 无GPU
- 模型走云端API（SenseNova + Agnes + GLM，全免费额度）
- 后端：`systemctl restart som-api`（Python 3.11）
- 前端：nginx 静态托管
- 足够支撑前期用户

**第二阶段（用户量增长后）：**
- 升级服务器或租用GPU实例
- 部署更大模型（7B级别中医专用模型）
- 知识库持续扩充

## 数据自主与隐私

### 核心原则

- 所有用户健康数据存储在自有服务器
- 用户对话数据、辨证记录、体质画像完全归SOM所有
- LLM 调用仅发送当前对话，不上传用户数据库

### 数据壁垒

```
用户对话 → 辨证记录 → 体质画像 → 购买偏好 → 反馈数据
    ↓
持续积累 → 知识库越来越丰富 → 辨证越来越准 → 用户越来越信任
    ↓
这就是SOM的核心壁垒，别人抄不走
```

## 商品推荐铁律（v3 确立）

1. **必须有机** — 商品标题必须含"有机"二字，没有例外
2. **必须是食材** — 排除加工制品（原浆/口服液/养生膏/饮品/胶囊等）
3. **食材必须是商品主体** — "有机玉竹...搭百合煲汤"中百合只是搭配，不算
4. **每食材2款不同品牌** — 严格按食谱顺序
5. **食材别名匹配** — 大米→有机米/胚芽米/稻花香，老鸭→鸭，生姜→姜
6. **宁缺毋滥** — 搜不到有机认证的食材就不推，不硬凑非有机的

## 差异化护城河

### 核心判断：别在体验上跟淘宝刚，要在专业度上让淘宝够不着

**SOM 的不可替代性（淘宝给不了的）：**

| 维度 | 淘宝 | SOM |
|------|------|-----|
| 商品组织 | 按品类堆（搜"有机小米"） | 按养生方案配（"气虚补气套餐""祛湿食谱"） |
| 决策依据 | 销量/价格/评价 | 体质测评 + 辨证结果（你是气虚质，该吃这个别碰那个） |
| 内容信任 | 商家自卖自夸 | 药食同源知识库 + 辨证逻辑，专业背书 |
| 用户画像 | 购买偏好 | 体质画像 + 证型 + 养生阶段 |

**一句话：淘宝卖货，SOM 卖"对症的养生方案"。货只是方案的载体。**

### 三层数据壁垒（越用越深，抄不走）

```
体质测评数据 → 辨证记录 → 养生方案效果反馈
        ↓
知识库越喂越准 → 辨证越准 → 用户越信 → 数据越多
        ↓
这是复利，不是功能，别人复刻不了
```

### 推广策略（冷启动）

1. **内容种草** — 公众号/小红书发"九种体质自测""节气食疗"，文末引流到测评
2. **社群渗透** — 中医养生群、宝妈群、亚健康白领群，体质测评是天然钩子
3. **测评裂变** — "测测你是什么体质"结果可分享，带二维码
4. **信任前置** — 先让用户觉得"这儿辨证准"，再谈买东西
