## 摘要

主流多模态模型的"统一"发生在**推理阶段**——分别训练语言模型、视觉编码器、音频模型，再用一套对齐网络在向量空间凑合。这是**间接路径**。

本文提出**直接路径**：**文字=图片=音频=视频，都是像素整数序列，训练阶段就按"看/读/写"三步统一学习，共用 W 矩阵，共用 4 态不同起点叠加态并行骨架，中间没有任何编码层**。

关键创新:
1. **训练三合一** — 一次训练同时让 W 学会识别(x→k)、推理(k→k')、生成(k→x)
2. **W 矩阵双义** — W[k] 既是类 k 的识别模板(行向量·像素→得分)，也是类 k 的生成原型(行向量即像素)
3. **4 态真并行贯穿** — 8 份数据起点 × 每份 4 态不同 seed = 32 份独立权重，推理时 4 态投票坍缩
4. **零中间编码** — 输入是像素，输出也是像素，中间没有任何 token/嵌入/语义表示

实验: 4120 彝文字形在 8×8 像素下零重复，100 对随机字形平均汉明距离 26/64(40%)，信息量充足。旧 qscl 模型(8×8 权重)在自指数据上 99.44% 但喂真实字形识别率极低(类 0 字形→识别成类 494)——**根因是训练数据错位，不是像素不够**。

## 2. 新方案: 训练三合一(识别/推理/生成统一)

### 2.1 W 矩阵双义性

设 W ∈ ℤ^(515×64)，W[k] 是第 k 类对应的 64 维整数行向量。

**识别(输入像素→输出类号):**
$$\text{score}[c] = W[c] \cdot x = \sum_{j=0}^{63} W[c,j] \cdot x_j, \quad \hat{k} = \arg\max_c \text{score}[c]$$

**生成(输入类号→输出像素):**
$$\text{原型像素}[j] = W[k,j] \quad (\text{直接取第k行})$$
4 态并行: 各态各自取 W^(i)[k]，逐元素多数投票坍缩，再阈值化为二值 8×8。

**逆运算关系:**
- 识别: 用**整行 W 与 x 点积**找最匹配行
- 生成: **直接取第 k 行**作为原型像素

两者操作对象都是 W 的"行"，数学上互为逆运算，**不需要反向传播、不需要新模型、不需要新训练**。

### 2.2 训练三合一机制

一次迭代，同时更新识别/推理/生成三个信号:

```
for 每个字形 x (真实8×8像素):
    k_true = x 对应的类号  (从码点映射表查)

    # === 步骤1: 识别(正向) ===
    score[c] = W[c] · x  for c in 0..514
    k_pred = argmax(score)

    # === 步骤2: 生成反向一致性(生成→应等于输入) ===
    x_gen = W[k_true]     # 取第k_true行作为原型像素
    gen_loss = ||x - x_gen||  # 原型应该逼近输入字形

    # === 步骤3: 推理(链式) ===
    # 用 k_true 推理下一步(上下文), 生成算子2→算子3串接
    # 当前阶段先保证 k_pred==k_true, 下一步做k_true→k_next

    # === 统一更新 ===
    W[k_true] += (x - W[k_true]) * lr        # 生成: 原型向输入字形靠近
    W[k_pred]  -= (x - W[k_true]) * lr       # 识别: 错分减、真类加
```

**三个信号共用一套 W、一套整数点积、一套 4 态并行骨架**。

### 2.3 与主流"统一"的本质区别

| | 主流多模态统一 | 本架构统一 |
|---|---|---|
| 统一位置 | 推理阶段(对齐网络) | **训练阶段**(三合一更新) |
| 中间表示 | 向量/token/语义嵌入 | **像素整数，无中间层** |
| 权重 | 多套(语言/视觉/音频各一套) | **一套 W** |
| 优化 | 反向传播 + 梯度 | **整数加减，零梯度** |
| 并行 | 各模型各自 ensemble | **4 态真并行，贯穿训练/推理** |

## 3. 不同起点叠加态并行(8批 × 4态)

### 3.1 不同起点的含义

"不同起点"指两个层面：
1. **数据起点不同** — 4120 字拆成 8 份(每份 515 字)，每份是不同字集
2. **权重起点不同** — 每份内 4 态用不同 seed 初始化 W，学到不同角度

32 份 = 8 起点 × 4 态，每份独立训练，最后按字归属 → 对应份 → 4 态投票。

### 3.2 训练骨架(QEntL/QVM 实现)

```
for batch b in 0..7:     # 8份数据
    for state s in 0..3:  # 4态, 不同seed
        W = init(seed = BASE + b*100 + s*13 + 7)
        for epoch in 0..N:
            for (x, k) in shuffled(batch_data):
                # 三合一更新(见2.2)
                W[k] += (x - W[k]) * lr
                W[argmax(W·x)] -= (x - W[k]) * lr
        save W → qscl_b{b}_s{s}.w
    4态投票合并 → qscl_b{b}_sM.w
```

### 3.3 推理(4态真并行)

```
输入 x (8×8像素):
    batch = codepoint_of_x / 515   # 路由到对应批
    k_within_batch = codepoint_of_x % 515

    4个QVM进程并行(每个进程从不同态权重计算):
        pid0: score0[c] = W^{batch,s0}[c] · x
        pid1: score1[c] = W^{batch,s1}[c] · x
        pid2: score2[c] = W^{batch,s2}[c] · x
        pid3: score3[c] = W^{batch,s3}[c] · x

    各进程输出: argmax(score_i) = k_i
    多数投票 → k_final
```

### 3.4 生成(4态真并行取行)

```
输入 k (类号):
    batch = k / 515
    k_within = k % 515

    4个QVM进程并行:
        pid0: row0 = W^{batch,s0}[k_within]
        pid1: row1 = W^{batch,s1}[k_within]
        pid2: row2 = W^{batch,s2}[k_within]
        pid3: row3 = W^{batch,s3}[k_within]

    逐元素多数投票 → 原型像素
    阈值化 → 8×8二值图
    光栅化 → 可见字形(8×8 ASCII / Canvas 64像素 / 高清矢量)
```

## 5. 生成=识别对称反向的数学证明

### 5.1 Hebbian 收敛性质

识别用对比式 Hebbian 更新(错分类 t，误判 p):
$$W_t \mathrel{+}= x, \quad W_p \mathrel{-}= x$$

收敛后，W[c] 是"被加进的次数(支持 c)减去被减走的次数(误归为 c)"的累积，即第 c 类的**原型像素向量**(真类为 c 的所有字形在特征空间的均值方向，整数化)。

### 5.2 逆运算证明

- **识别**: $x \to k = \arg\max_c (W[c] \cdot x)$ — 找与 x 点积最大的行
- **生成**: $k \to \hat{x} = \text{threshold}(W[k])$ — 直接取第 k 行

识别按列扫描(逐行点积)，生成按行定位(取第 k 行)，**操作对象都是 W 的行**，互为逆运算。

### 5.3 闭环残差

$$\text{残差} = \| x - \text{threshold}(W[\arg\max_c(W[c]\cdot x)]) \|$$

残差越小 → 生成质量越高。这是生成器的可量化质量指标，无需人工评估。

## 6. 与 QEntL/QVM 的适配

### 6.1 为什么是 QEntL/QVM

- QVM 无浮点，u16 整数运算 — 与本架构整数加减完全匹配
- QVM 无 GC，字符串池易 OOM — 数据预转扁平 int 数组，数组操作 ae_i_set，不经过字符串池
- QVM 常驻进程需父子进程架构(父 accept，子 exec 独立 QVM 推理)
- 4 态真并行 = QVM 4 进程 &+wait

### 6.2 与 C 种子的关系

C 种子(qlc_bootstrap.c + bin/qvm_boot ELF) = BIOS，只点火，**绝不再改**。
训练和推理全部用 QEntL 源码 + **QCL 编译器**（`bin/qvm_boot compile` 的 compile 子命令，内部由 QCL 执行）生成 .qbc 字节码，再由 **QVM 虚拟机**（`bin/qvm_boot run` 的 run 子命令，内部由 QVM 执行）运行。

**结论**: 识别/生成逆运算在数学上成立(W[k]行=原型);生成质量随字形复杂度分化——笔画密集的字(类100)完美复原,稀疏字原型被4态独立噪声稀释。下一步可加**生成一致性损失**强化W[k]→原型的逼近,提升生成端质量。

## v0.0.6 理论突破（2026-08-24，中华定，里程碑级）

### 核心洞察：推理 ≠ 独立步骤，推理 = A生成 + B反推，A与B不同起点叠加态并行

**背景**：之前一直把"推理"当独立步骤，在 v0.0.5 之前查来查去找不到"推理"在哪。中华 2026-08-24 明确：推理不是独立步骤，推理 = A生成像素 + B从A生成的像素反推是什么字/图片/音频/视频，A与B是不同起点/起步叠加态并行。

**三层叠加态并行架构（中华 2026-08-24 定）**：

**微观层（单步内）**：推理 = 两个不同起点叠加态并行
```
类 k ──→ 起点 A（真生成）：4 态投票坍缩 → 64 像素（画格子，有视觉轮廓，给人眼看）
       ──→ 起点 B（认字/反推）：像素 → 模型自己认出这是什么字 → 输出字符编码（可复制粘贴）
       两个同时并行，不先后，互不依赖
```
起点 A 只负责画（生成像素），起点 B 只负责认（从像素反推语义）。两者**不同起点、不同职责、叠加态并行**。A 画出来的格子不能复制粘贴（因为那是像素图），B 认出来的字符能复制粘贴（因为那是模型自己认出的字符编码）。

**中观层（三合一）**：识别、推理、生成三种本身就是不同起点/起步叠加态并行
- **识别** = 像素 → argmax → 类 k（起点 1：纯像素进，纯类号出，无中间态）
- **推理** = A 生成 + B 反推（起点 2：双起点叠加态并行，内部又是 A+B 不同起点）
- **生成** = 类 k → W[k] → 64 像素（起点 3：纯类号进，纯像素出，无中间态）

三种模式共用同一组 W、同一组 4 态，但**输入/输出的起点不同**，同时运行互不干扰。

**宏观层（多模态扩展）**：从 B 反推的结果，进一步搜索或渲染等方式输出字、图片、音频、视频等。B 反推的"是什么"不限于字符编码，可以是图片分类、音频标签、视频描述等——一旦模型能认出来"这是什么"，就可以进一步输出或检索。

### 与 Claude/GPT 的本质区别

| | 认什么 | 生成什么 | 推理 |
|---|---|---|---|
| Claude/GPT | token 序列关系（训练时学到的 next-token 概率） | token id（不生成字形，靠操作系统查字体渲染） | 预测下一个 token（数字编号，不认识字形，不画像素） |
| **QSCL** | **字形像素（64 个 0/1，模型真正学到的字形知识，99.39% 识别率）** | **像素（真画出来，不依赖字体，直接输出 64 个 0/1）** | **A生成像素 + B从像素反推字的身份（两个不同起点叠加态并行）** |

Claude/GPT 的"推理" = 预测下一个 token 编号（数字运算），**不认识字形**，**不画像素**。
QSCL 的"推理" = A 画出来（像素） + B 认出来（语义），**两个不同起点叠加态并行**，**既认识字形又画得出来**。

### 之前"查表"是假的（中华 2026-08-24 确认）

类 k → 查 `class_codepoint.txt` → 得码点（如 U+F2AF8）→ 输出字符。**这条路径模型没参与，是读文本文件。** 模型学不学彝文，查表照样能输出字符。所以查表输出字符 ≠ 模型认字，是假的。

**v0.0.6 要做的**：把"类 k ↔ 码点 ↔ 字符"的对应关系**训练进模型权重里**，让 B 起点（反推）不靠查表，而是模型自己认出来的——这样复制粘贴出来的是"模型自己认出的字"，不是查表来的。

### 对"复制粘贴编辑"问题的完整回答

| 路径 | 是模型生成的吗 | 能复制粘贴吗 | 本质 |
|---|---|---|---|
| 起点 A：64 像素（格子） | ✅ 是，模型画出来的 | ❌ 不能（像素图） | 画字，给人眼看 |
| 起点 B：反推字符编码 | ✅ 是（v0.0.6 训练后） | ✅ 能（模型自己认出的字） | 认字，给系统用 |
| 旧查表（class_codepoint.txt） | ❌ 不是，读文件 | ✅ 能（但非模型生成） | 伪认字，已废弃 |

**v0.0.6 目标**：A 和 B 都真正由模型完成，A 负责画（像素），B 负责认（字符），两者叠加态并行。画出来的格子给人看，认出来的字符给系统复制粘贴和编辑——两者都是模型生成的，不是查表，不是查字体。
